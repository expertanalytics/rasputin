# 20c-1 re-time after the split-phase fix 69f37d1c (@perf, 2026-10-07)

Branch `worktree-soft-quality`, code at `69f37d1c` (`@developer`'s fix
under ruling 5: compute `foot_epsilon` only where a constrained edge is
within reach), against master `ed125121`. This re-times the first
acceptance (`../README.md`, code `34b546c4`, commit `b9e2d482`). The rules
are the same: `docs/increments/20c-soft-quality.md`, "Rulings on 20c-1's
green step" item 5 (the split phase, feet on against
`--no-constraint-feet`, 2 % limit), and `docs/increments/README.md`,
"Acceptance".

## Verdict

- **1 m benchmark and thread sweep: ACCEPTED.** The meshes are
  byte-identical to master's. Refine is 0.3 % to 2.0 % faster than master
  at every thread count, against master's own run-to-run spread of up to
  1.8 %. The 1-to-20-thread speed-up is 2.56 x (tile) and 2.54 x (quarter)
  for 69f37d1c, against master's 2.55 x and 2.51 x. The first acceptance's
  +6 % to +24 % is gone.
- **Split phase, feet on against feet off (ruling 5): over the 2 % limit
  on both catchments, within it on the 1 m tile.** The medians are +0.86 %
  on the tile, +7.1 % on Lagan and +6.7 % on Numedalslagen. Per split, they
  are +0.86 %, +8.3 % and +8.9 %. Feet on does fewer splits than feet off on
  both catchments, so the per-split figure is the larger one. On both
  catchments the fastest feet-on run is slower than the slowest feet-off
  run, so the gap is not noise.
- **Against master's default** the split phase is now faster: −0.4 % (tile),
  −3.3 % (Lagan), −7.7 % (Numedalslagen); per split −0.4 %, −2.5 %, −7.5 %.
- **Not in ruling 5's phase, but measured:** `refine: start quality` is
  +6.9 % (Lagan) and +5.7 % (Numedalslagen) feet on against feet off, and
  +7.7 % and +6.5 % against master. Whole `refine` is +4.7 % and +3.8 %
  against feet off. Nothing has been profiled. Why per-split cost is higher
  with feet on is **not known**: it could be the remaining `foot_epsilon`
  work or the foot placement itself.
- **Byte-identity: confirmed.** Every 69f37d1c mesh (feet on and feet off,
  tile and both catchments) equals the first acceptance's raw output: the
  hash of the arrays and of the `.vtk` from `POINTS` on. Master's meshes
  equal too. The 20c-1 gates all pass with the same figures as before.

## Method

- **Machine and power.** Apple M1 Max, macOS 27.0, 10 hardware threads.
  AC power for every run, battery 100 % charged throughout. `pmset -g batt`
  was read before and after each run (`raw/*.power`; `run.json` `power` for
  the benchmark). The scripts stop before a run off AC and set aside a run
  whose power changed; none was set aside. `pmset -g log` shows no sleep,
  wake or power-source event between 06:15 and 07:10 local time (runs
  04:20Z to 05:10Z).
- **Builds.** `tools/bench.py`'s `build()`: Release `-O3 -DNDEBUG`,
  AppleClang 21, hardening on (`libc++ fast` in every run), into
  `<tree>/build-bench/pkg`. Base: a scratch worktree of `ed125121`
  (`_core` sha256 `19d71363…`, the same as the first acceptance's base).
  Head: this worktree at `69f37d1c` (`86765ff1…`). Every run loads the
  package from its `pkg` tree and prints `tin_engine.__file__` and
  `_core.__file__` (first lines of each `raw/*.log`); `drive.py` refuses
  to run when either comes from elsewhere. Python: this worktree's `.venv`
  (Python 3.14). The head run records `dirty: true` because this directory
  was untracked during the runs; nothing outside it differed from
  `69f37d1c`.
- **1 m benchmark** (`pairs.sh`; log `bench/pairs.log`): `tools/bench.py
  run` with its defaults: the tile and `docs/benchmarks/2026-09-26/quarter.geojson`,
  tolerance 1, threads default and 1 to 20, 5 repeats, hardening on.
  Three pairs, order base, head, head, base, base, head. The verdict lines
  `bench.py` printed (in `pairs.log`) compare each run with the previous
  stored run; the pooled table from `bench_summarize.py` (copied from `..`)
  is the one that counts.
- **Phases** (`run.sh`, `drive.py`; log `runs.log`): the tile (tolerance
  1), Lagan and Numedalslagen, with the commands of the first acceptance.
  Three builds: master, 69f37d1c, and 69f37d1c with `--no-constraint-feet`.
  Seven repeats (r0 to r6), order reversed on every other repeat; r0 is a
  warm-up and is left out of the timing medians. Master with
  `--no-constraint-feet` was not rerun: the gate row compares with its
  raw output in `../raw`. Splits per run are `points_inserted` from the
  `--stats` file. Threads: the CLI default (10).
- **Tables** below are generated by `python3 summarize.py`, which reads only
  `raw/`, `bench/`, and for identity and gates `../raw/` and `../raw1m/`.
- **Meshes** were in the session scratchpad and are not kept. To
  regenerate them, make a worktree of `ed125121` at the path in the
  scripts, then run `pairs.sh` (it builds both trees) and
  `run.sh 0 1 2 3 4 5 6`.
