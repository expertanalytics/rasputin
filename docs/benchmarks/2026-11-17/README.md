# gcc15-predicates: acceptance timing, 2026-11-17

The change measured: head `d029ffbf` (branch `worktree-gcc15-predicates`)
builds the whole core with `-ffp-contract=off`. That flag stops the compiler
fusing a multiply and an add into one instruction, which made the exact
predicates inexact under GCC. The base is master `72cc84ac`.

## Result

**Verdict: REGRESSION**, with AppleClang on the quarter domain only.

- **Meshes:** byte-identical to master's in every run, with both compilers
  and both domains. The mesh sha256 and every quality figure match:
  - worst angle 0.63 degrees on the tile, 0.40 on the quarter;
  - highest vertex degree 74 on the tile, 18 on the quarter;
  - every point within tolerance;
  - no Delaunay violations.
- **AppleClang, on AC:**
  - Refine on the quarter domain is 5.4 % slower at the default thread
    count, 18 % slower at 1 thread, and mostly 5 % to 9 % slower from 4 to
    20 threads.
  - The whole tile is flat, between -1 % and +3 %.
- **g++-16, on AC:** no slower. Refine is 3 % to 9 % faster on the tile and
  0 % to +1.4 % on the quarter.
- **Cause:** thought to be, not profiled. AppleClang's default fuses within
  one expression, and the head build loses that. The quarter run is thought
  to spend a larger share of its time in the predicates and in clipping to
  the domain.

**Open question for Ola:** do we accept about 5 % to 9 % slower AppleClang
refine on clipped domains (up to 18 % at 1 thread), in exchange for exact
predicates on every compiler?
- Recommended: yes.
- A profile of the quarter domain follows next week.
- A possible follow-up: apply `-ffp-contract=off` to the predicate code only.

## Method

- **Machine:** Apple M1 Max, 8 performance and 2 efficiency cores, 32 GiB.
- **Load:** the load average was 34 at 16:57, with the CPU nearly idle at
  that moment. Chrome was not running. Every run is a detached job, with
  nothing else running beside it.
- **Builds:**
  - Release, with the standard library's bounds checks on: libc++ "fast"
    for AppleClang 21.0.0, libstdc++ assertions for GNU 16.2.0.
  - Each tree is built in its own `build-bench`.
  - The g++-16 trees are separate worktrees, configured with
    `CXX=g++-16 CC=gcc-16`.
- **Inputs:** DEM `tests/fixtures/dem_archive/7908_3_10m_z33.tif`, tolerance
  1. The domains are the whole tile and
  `docs/benchmarks/2026-09-26/quarter.geojson`.
- **Commands:** `tools/bench.py run` from head's `.venv`, with bench.py blob
  `16ad2ff52bdef716a23214fa4c877a497a2bef6c` and these options:
  - `--tree <base or head> --label <run> --baseline <base run dir>`;
  - `--threads 1,8` for g++-16; the default 1 to 20 for AppleClang.
- **Sanitizers, before any timing:** an AppleClang build with
  `-fsanitize=address,undefined` and `-ffp-contract=off` (head's
  `build-san`) passed `ctest` 1052 of 1052.
- **Meshes** are not kept. To regenerate one, rerun the child command in a
  run's README with `--ascii --out PATH`.
