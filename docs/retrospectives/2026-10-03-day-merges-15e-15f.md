## 3. Lessons

### 3a. Absolute tolerances in a design need a scale check

Ruling L12 (801ccff, 13:28) put a point "within 1e-10 cells" of a constraint
edge onto the edge, and L14 (72c4175, 13:46) skipped one within 1e-10 of a
vertex. Both are fixed absolute thresholds in lattice units. At 13:50:11 Ola
queued "Can you explain the 1e-10 reasoning for me?" (transcript line 2632,
a queued prompt). Writing the answer, the main session found that one ulp at
lattice coordinate 10⁶ is about 2.2e-10, above the threshold (line 2678). At
13:58:39 Ola said "yes, have architect check" (line 2740). `@architect`
confirmed it and ruled L16 (3b59934): `r(g) = max(1e-10, 64 ulp(M))`, with M
the largest lattice coordinate. The same day's largest real window (the whole
basin at 30 m, 50,296 nodes) already needs 4.7e-10.

Nobody on the design, red, green or review side raised it; Ola's question
did. The test side made the same mistake on its own (3c below): ES16 bounded a
height error by an absolute 1e-9 where the true value is slope × offset.

The general rule is old: a fixed absolute epsilon stops working once the
numbers grow, because the gap between doubles grows with them; compare in
ulps or relative to the magnitude (Bruce Dawson, "Comparing Floating Point
Numbers, 2012 Edition", randomascii.wordpress.com, read 2026-10-03). The L16
ruling's table, which states the radius at each real lattice size, is the form
worth repeating: every absolute constant in a design gets the scale it assumes
and the largest input it was checked at.

### 3b. A local default build on arm64 hides what CI's x86-64 runner sees

ES13 failed at sweep seed 11, k 37, tolerance 0, only when built with
`-ffp-contract=off` (the main session's brief to `@architect`, transcript line
2397). Apple Silicon fuses multiply-adds by default; CI's ubuntu x86-64 runner
builds for baseline x86-64, which has no FMA instruction, so it rounds each
step. The failure was caught before any push because `@developer` builds both
ways (`.claude/agents/developer.md@586fbc1:30`, a standing rule). It
worked as intended. Two gaps remain: `tester.md` does not carry the same line
(`@tester` ran both builds today because its brief asked), and project-wide
`-ffp-contract=off` is an open question in `session.md`.

each increment file has a status line. Together with 2e, this suggests the
ROADMAP's status column should come from the increment files, not be written
by hand in every PR.
