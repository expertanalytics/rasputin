## 2. Why #283 failed, and how to avoid it

What happened: `docs/retrospectives/2026-10-17-overdue-check-night-merges-audit.md`
(#282) cited test lines without pinning them to a commit
(`tests/python/test_plugin_api.py@61755c04:49`,
`tests/python/test_reference.py@61755c04:546`,
`tests/python/test_legend_name.py@61755c04:151`; here pinned to #282's merge).
Increment 67, built at the same time from that same audit, deleted those
lines. Each branch passed `check_citations.py` against master on its own.
#282 merged at 12:44. #283's first run, at 12:49, checked out a tree that
had both, and three citations no longer resolved.

Two costs:

- **51 minutes unnoticed.** The check failed at 12:49:47. The main session
  saw it at 13:40:59. Its watcher (transcript 12:52:17) looped until the PR
  was `MERGED` or `CLOSED`. A PR with a failed check is neither: it stays
  `OPEN`, so the watcher would have run for its full 2 hours.
- **About 1 h 35 min from push to merge.** The other four took about 20
  minutes each.

How to avoid it:

1. **A retrospective pins every code citation when it is written**
   (`path@<sha>:line`). A retrospective describes the tree at one moment, so
   a pinned citation is always correct, and an unpinned one breaks when the
   code changes. I pinned the four that were left in the 2026-10-17 file, in
   this commit, to `df923398` (two had already drifted: the push-form table
   in `tools/push_grant.py` and the first absence test in
   `tests/python/test_cli_help.py` now sit at other lines). Four backticked
   unpinned code citations remain in older retrospectives. The first draft
   of this file repeated the mistake three times. The gate caught it only
   because those lines are already gone. So option 1 is not enough on its
   own.
2. **Proposal (a gate):** `tools/check_citations.py` fails an unpinned line
   citation from `docs/retrospectives/` into code, just as it already fails
   one into a rule file (`GOVERNED`). Cost: about 5 lines, plus pinning the
   four. It stops this kind of failure for good. Option 1 alone depends on
   my remembering.
3. **Watchers stop on a red check:** wait with
   `gh pr checks <pr> --watch --fail-fast` (checked in `gh pr checks --help`),
   then wait for `MERGED`. Cost: nothing; the brief text changes.

  coordinates in the increment file (`@architect`, 66).

  run (66, `80d3e2ce`). Read the summary before writing the message.

  that read harness logs (`reviews.jsonl`, the away-window log) were refused
