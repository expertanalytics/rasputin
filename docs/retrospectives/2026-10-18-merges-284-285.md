## 3. The grant could not push 66

At 14:41:57 the main session pushed `a5ae6356` under the away grant for
`worktree-coincident-vertices`. The guard refused it (queue line 12): "head
a5ae635 is not reviewed: commit 5eee02e changes
docs/benchmarks/2026-10-17/66-coincident-written-vertices/bench-base/raw.tsv
after the review of edd6f02".

The cause is a gap between two rules. `docs/increments/README.md` puts
`@perf`'s acceptance run after the code review, so its evidence commit always
follows the verdict. `tools/push_grant.py@9c80b7de:227` (`changes`) allows
only prose after the review, and prose is a Markdown file
(`tools/ci_changes.py@9c80b7de:44`). `5eee02e8` adds `.tsv`, `.json` and a
`delta.py` under `docs/benchmarks/2026-10-17/`. So every increment that
touches refine or mesh code cannot be pushed under a grant.

**Proposal (harness; Ola decides):** in `changes`, a commit after the review
also passes when it only **adds** files under a dated
`docs/benchmarks/<YYYY-MM-DD>/` folder. Adding only, so `@perf` cannot edit
earlier evidence. Dated, so `docs/benchmarks/quick/` and the stored
quarter outline, which `tools/bench_quick.py` and `tools/bench.py` read, stay
code. Cost: about 5 lines in `tools/push_grant.py` and two tests (one
allowed add, one refused edit of `docs/benchmarks/quick/`). It is a governed
file, so it is built by day with Ola's yes.
