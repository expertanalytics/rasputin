## 6. Proposals, with evidence

The 2026-10-18 day retrospective found that a lesson kept in the main
session's memory fades (its section 6, Ola at 06:52). So each fix below
lives in a tool or a hook, not in a sentence.

1. **`away.py` refuses to enter while a prompt is waiting** (2.2). On
   entry it reads the main session's newest transcript under
   `~/.claude/projects/<project>/`, finds a tool call with no result whose
   `PreToolUse` hook output says `"ask"`, and prints "A permission prompt
   is waiting in the session: `<command>`. Answer it, then run away.py
   again." The `--back` report adds each prompt that waited longer than
   5 minutes, with the wait, beside the longest stretch without a commit,
   so the cause is printed and not guessed. Evidence: 15:20:21 to 16:41:14,
   81 min, and line 237's wrong cause. Cost: about 40 lines in
   `tools/away.py` (governed, by day) and three tests. Would have saved
   1 h 21 min of 69's wait and the three granted pushes behind it.
2. **A notification when a prompt waits** (2.3). A `Notification` hook
   with the matcher `permission_prompt` (an event type listed in the
   Claude Code hooks reference, `code.claude.com/docs/en/hooks`, read for
   this check) runs `osascript -e 'display notification …'`, so a prompt
   shows on the Mac even with the terminal hidden. Evidence: 17:01:50 to
   20:14:46. Cost: about 5 lines in `.claude/settings.json` (Ola's edit),
   no test. Whether a Mac banner reaches Ola when he is away from the
   desk is for him to say.
3. **A Stop hook for the 10-17 kind** (not today's). While unattended mode
   is on, the first attempt to end a turn is blocked once
   (`"decision": "block"`, documented in the same reference) with the
   reason "Unattended: name the work running, or start the QUEUE
   fallback"; the second is let through (the hook input's
   `stop_hook_active`, unchecked: the part of the page I read did not
   show the field). Evidence: 10-17 19:49:34 to 21:15, 1 h 26 min
   (`2026-10-18-merges-284-285.md`, section 4, "Window 19:50-21:16"). Cost: about 20 lines in
   `guard_unattended.py`, a `Stop` entry in `.claude/settings.json`, two
   tests; one extra model step per turn end while away. It would not have
   helped today.
4. **The machine `Review:` line in the brief** (carried from
   `2026-10-18-day.md`, proposal 1). Ola's 15:17 answer put question 3 on
   hold ("does not make sense"); line 235 says "Question 3 not answered
   yet". PR D's push still needed a `@reviewer` resume at 20:14 for
   exactly this. Restated in plain words for him: the tool that writes
   each reviewer's instructions would print the exact last line the
   reviewer must end with, so the hook that records approvals can always
   read it.
5. **Private master waits for green** (4.2). Either protect private
   `master` with its one CI job as a required check, so `gh pr merge
   --auto` waits as it does on public `master`; or, with no protection,
   merge a private PR only after `gh pr checks <n> --repo
   expertanalytics/rasputin-private --watch` exits 0. The first is one
   setting on GitHub (Ola's; it may need a paid plan for a private
   repository, unchecked) and no code; the second is a habit, which the
   2026-10-18 finding on fading lessons argues against, unless the
   away-mode grant for the private repository checks it. Evidence: #11
   merged 9 min 44 s before its run ended.
6. **A failed nightly reaches the recap** (4.3). `tools/session_state.py`
   lists the last scheduled run of each repository's `master` when it
   failed, with its first error line (`gh run list --event schedule -L 1`).
   Evidence: two failed private nightlies, unread for about 29 hours, on
   the break 61 then found by hand. Cost: about 15 lines in a governed tool
   and a test.
