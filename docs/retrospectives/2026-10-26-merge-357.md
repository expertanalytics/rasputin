## 3. Lessons from the personas today, with their fixes

- **`ruff --exclude` replaces the config's excludes.** Use
  `--extend-exclude` to add to them.
- **A re-review brief names the CI state of the head it sends** (pushed or
  not, green or red). Fix as a tool: `tools/brief.py` prints `gh pr checks`
  for a reviewer brief's head. No rule words.
- **`pytest -n auto` needs pytest-xdist in the venv.** A private-repo green
  step ran its 4,862 tests one at a time for 8 min 18 s (transcript 33109).
  Fix: add pytest-xdist to that repo's dev dependencies.
- **A design that moves a function's body lists every caller**, found with
  `git grep`.
- **A refusal that only guards a caller against its own bug encodes a limit
  nobody chose.** A private design note refused weather windows off the whole
  hour; it hid an hourly-step assumption that the note then removed.

## 4. Proposals (Ola decides)

1. **Push before the re-review, so CI and review run side by side.** For a
   head that only merges master or fixes a test, the main session asks for
   the push first. The reviewer then reads CI on the head it judges, and no
   round is spent on CI alone. Cost: none in the rules; one question to Ola.
2. **Red CI blocks only on the head under review.** In `reviewer.md` §5,
   "**Red CI is an automatic `CHANGES REQUESTED`**" becomes "**Red CI on the
   head under review is an automatic `CHANGES REQUESTED`**; CI not yet run on
   it is stated, not judged". This is safe because the merge queue runs CI
   before any merge. Cost: +14 words, paid by proposal 3.
3. **Cut a restatement in `reviewer.md`.** Feedback item 3's example list
   "(e.g., red CI, exceeding the LOC ceiling, surviving red-step scaffolding,
   a prose claim the change made false)" repeats the mandate paragraph. Net
   −17 words; with proposal 2, −3.
